# Differences between the design chat and the pinned repositories

The design for spark-membrane came from a chat. The spec file it referenced was not available, so the build worked from the chat. Wherever the chat and the repositories differ, **the repositories win**. Checked on 2026-10-05 against the commits in [`PINS.json`](../PINS.json).

| # | Chat said | Repositories say | What spark-membrane does |
|---|---|---|---|
| 1 | `oes32-residual` pinned at `b77b612`. | `b77b612` is the ADR-001 normative commit, but HEAD is `7277e0f` (8 later commits: docs, CI, licence, citation). The contract files are byte-identical between the two. | Pins `b77b61254f15778c6ae221843dceac7a8571158e` and records HEAD in `PINS.json`. |
| 2 | Profile A: SAFE = A ∧ C0 ∧ C1 ∧ Cfold, LATCH = ¬SAFE. | Matches the `oes32_engine` code (`Evaluation.latch = not safe`). Its README also writes `L = 1[R > τ]` for the coherence latch alone, so "latch" means two things there. C0, C1 and Cfold are computed on the observed vector itself, not on the residual. With the default antisymmetric odd sector and τ = 0.08, any SAFE frame has every component within about ±0.08. | Follows the code. Demo frames sit near a zero reference so nominal frames can pass. Reports A, C0, C1 and Cfold separately, each with its index pair. |
| 3 | EVEN/ODD symmetry and FOLD8 as one set of definitions. | Three different definitions share these names. `oes32_engine`: parity-based mirrored pairs and contiguous 8-blocks on x. `oes32-membrane-shield`: EVEN/ODD as first-half mirror checks and FOLD8 as strided rings (i mod 4, step 4), all on the *delta*. `oes32-hls`: squared differences, `≥` rule, ring sums. The shield README says its sectors "correspond to the Profile A sidecar"; they don't match exactly. | Uses the `oes32_engine` definitions only. |
| 4 | Capability gate from `oes32-membrane-shield`. | The shield verifies Ed25519 capabilities and depends on `cryptography` (`>=50,<51`), which the standard library can't replace. Its role and action enum values are lower-case (`decodeur`, `write`). | `shield.py` always applies the role table (DECODEUR/GARDIEN write; CALIBRATEUR+GARDIEN calibrate; EXPLORER never), and role policy alone never admits. With the optional `[shield]` extra it verifies upstream-format capabilities (same JSON fields and signed bytes; CI exchanges capabilities with the upstream library in both directions). Without it, every signed capability is refused. |
| 5 | Two live OES-32 formulas; the weighted one comes from `oes-resilience` / `oes-telemetry-bench`. | Correct. But ADR-001 (in `oes32-residual` and `oes32_engine`) still says the weighted latch `0.45/0.35/0.20 @ 0.50` is "TARGET / unpublished". `oes-resilience` has published it (formula and default threshold 0.50 since v0.1.0; now `OES32Detector.default_threshold = 0.50`), and so has `oes512-residual`. The ADR text is out of date. | Treats the weighted score as published by `oes-resilience` at the pin, with the uncalibrated default 0.50. Never blends it with the residual. |
| 6 | "The bench already says the residual function is present and unused." | Confirmed: the `oes-telemetry-bench` report lists `residual_reference.evaluate_residual` as a different, unused algorithm. | Runs both, as separate checks. |
| 7 | Frame bus: native 32-channel JSONL; "512 is 16 of those blocks". | The bench contract is strictly 32 channels per record, with no 512-channel record format. `oes-resilience` handles 512 channels as 16 blocks inside one array and pools EWMA/CUSUM σ across blocks. | Carries 512 channels as 16 separate native-32 streams with shared timestamps; global index = 32·block + channel. EWMA/CUSUM are standardized per block on that block's own separate calibration stream, which differs from `oes-resilience`'s pooled σ. |
| 8 | ACCEPT iff residual passes ∧ weighted doesn't alarm ∧ protocol hash matches. | (Design choice, not a repo fact.) | The gate also includes the Profile A sidecar from the contract spine (stricter, fail-closed). Max-abs, EWMA and CUSUM are advisory. |
| 9 | SMAP/MSL: "OES32 did not meet its success criterion (v0.5.0)". | Exact wording: "OES32 did **not** meet its pre-stated success criterion: it beat only EWMA on SMAP, and `maxabs` and CUSUM scored a higher pooled F1 (not significantly)." The run's metadata version string reads 0.4.0 (lock-commit code). It is real public data, adapted *univariately*: the 32 values are 32 consecutive samples of one channel, not 32 channels. Tag `v0.5.0` is `85dc5e6`; HEAD `1ee533c` adds docs only. | Quotes the repository wording and pins HEAD. |
| 10 | Synthetic telemetry demo: max-abs matched OES32 with fewer false alarms. | Confirmed in `reports/synthetic-demo-report.json`: 6/7 events each; 1 vs 2 false-alarm episodes; 11.54 vs 23.08 per normal hour, from about 5.2 minutes of synthetic normal time (the bench calls these rates highly uncertain). The alarm rule is `score >= threshold`, with thresholds calibrated on a separate replay. | Quotes it with the uncertainty caveat. |
| 11 | `multi-quantum-oes` published a negative stress result. | Confirmed: "Verdict: no demonstrated advantage." At fixed 0.50 the block score found 5/11 events and max-abs 8/11; calibrated, both found 0/11. The same repo also reports a negative toy-kernel result. | Quoted as SYNTHETIC, negative. |
| 12 | HLS synthesis and the qLDPC kernel are UNRUN. | Confirmed. `oes32-hls`: "FPGA synthesis is UNRUN"; the latency is a TARGET. `qldpc_decoder_cpp`: the BP kernel is a placeholder; HLS synthesis, timing and HIL are UNRUN. | Quoted as UNRUN. |
| 13 | `signal-loom` is an art skin. | Confirmed (performance-art prototype). It is MIT-licensed, unlike the AGPL siblings. | Linked only; nothing from it enters the audit. |
| 14 | `oes32_engine` (repo name to be found). | The repository is `sparkainlp-x/oes32_engine`, with an underscore. | Pinned under that name. |
| 15 | EWMA/CUSUM as baselines (no calibration detail). | `oes-resilience` and `oes-telemetry-bench` standardize the block mean on the first 16 steps of the evaluated stream itself (those steps are not scored) and define **no reset after an alarm**. On the very quiet demo warm-up this kept EWMA/CUSUM alarmed for the rest of the v1 demo (19 frames with engine disagreement). | v2 standardizes on a separate 64-frame event-free calibration stream (same noise model, never audited) and restarts each detector after an alarm. Both are author choices, listed in `docs/PROTOCOL.md`. The upstream in-stream behaviour is kept for conformance tests and as the `audit` fallback. Seed 42 now shows 7 frames with disagreement, all on event frames. |

Two smaller upstream inconsistencies came up along the way. First, the evidence-passport README said quantum-claims-passport had "No DOI yet", but that repo has concept DOI 10.5281/zenodo.23167801. This is fixed upstream in evidence-passport `e275bb0`, which also adds the DOI to its `CITATION.cff` and `.zenodo.json`, and spark-membrane now pins that commit. Second, `oes-telemetry-bench` needs NumPy, while spark-membrane stays standard-library only (NumPy is installed only in the CI `upstream` job).
