# Contributing to spark-membrane

Thank you for helping. Keep changes small, explicit and easy to review. Report security issues privately as described in [SECURITY.md](SECURITY.md), not as public issues.

## Ground rules

- **Synthetic data only.** Never commit private, proprietary, personal or operational data, including telemetry "just for a test". Every frame in this repository is generated by a seeded script.
- **Report losses as honestly as wins.** The README and page lead with the results that do not flatter OES32. Do not reorder, soften or remove them. Any number in the README or docs must come from a command in this repository (state the command and seed) or be quoted from a pinned upstream commit.
- **No overclaims.** This is a classical software simulation. It is not a medical device, not control software, not sensor fusion and not field evidence. Do not add claims of superiority over any benchmark, or claims about physical or biological systems, or about any hardware this code does not run on. The claims gate and `tools/forbidden_terms.py` enforce this in CI.
- **Fail closed.** No change may let an advisory engine, the explorer, a tampered protocol or an unverified capability produce ACCEPT or a write. The explorer may never modify the reference, a threshold or the original frame.
- **Pin, don't copy.** Upstream logic lives in the pinned repositories ([`PINS.json`](PINS.json)). A re-implementation must be small, labelled with its upstream commit, and tested against outputs of the pinned upstream code (`tools/make_upstream_fixtures.py`, `tests/test_upstream_live.py`).
- **Thresholds are placeholders.** If you change one, update the protocol, its `provenance` entry and [`docs/PROTOCOL.md`](docs/PROTOCOL.md), and relock `SHA256SUMS`. Never describe a value as calibrated unless a committed, reproducible calibration produced it.
- **License.** AGPL-3.0-only (see [LICENSE](LICENSE) and [COMMERCIAL-LICENSE.md](COMMERCIAL-LICENSE.md)). By contributing, you agree that your contribution is licensed under the same terms.

## Before you open a pull request

Run the checks CI runs:

```bash
python3 -m unittest discover -s tests -v       # stdlib only
python3 -m spark_membrane demo --seed 42
python3 -m spark_membrane build-docs --check   # docs/ and root mirrors match a fresh build
python3 -m spark_membrane shield-selftest
python3 tools/forbidden_terms.py
```

If you change anything that feeds the demo, run `python3 -m spark_membrane build-docs` and commit the regenerated `docs/` and root mirrors. To run the live upstream conformance tests, check out every repository in `PINS.json` at its pinned commit under one directory and set `SPARK_MEMBRANE_UPSTREAM` to that directory (needs NumPy, pytest and `cryptography`).

Update [`CHANGELOG.md`](CHANGELOG.md) for any user-visible change. Use conventional commit-style subjects where practical, such as `fix: refuse capabilities without a signature backend`. Pull requests should state what changed, why, how it was tested, and what risks remain.
